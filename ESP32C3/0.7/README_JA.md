# APRS iGate ESP32C3 v0.7

XIAO ESP32C3 + DRA818V / 144.640 MHz受信専用。秋葉原技研 / PS Ham-ware。
**v0.7は設置したまま診断・更新するための版です。感度と通常時の復調アルゴリズムは変更していません。**

## 初回はUSBで導入

現在のv0.5ではWeb OTAが約3.5秒で通信断になる事象を確認しています。原因は未確定です。
更新先のファイルだけでは動作中のOTA受信処理を修正できないため、**今回はUSBでv0.7を導入してください。**

- Arduino IDE 2.3.10 / ESP32 Core **3.3.12** / Board **XIAO_ESP32C3**。
- Flash Size **4MB** / USB CDC On Boot **Enabled**。
- Partition Scheme **Default 4MB with spiffs (1.2MB APP/1.5MB SPIFFS)**。No OTA / Huge APPは使用しません。
- `APRS_iGate_C3_Rev0_7.ino`と全`.h`を同じフォルダーに置き、Arduino IDEでUSB書き込み。
- 通常は全フラッシュ消去を無効にし、既存のWi-Fi・APRS・位置・OTA設定を継承します。
- 同梱OTA用`.bin`はアプリ単体で、初回USB用mergedイメージではありません。

## 本体ログ

管理画面の **本体ログ / Device log** または `/logs` から開きます。

- 本文上限**4096バイト**、RAM内リングバッファ。古い行から上書き。
- 各行に起動からの経過時間（ms）。日時ではありません。
- 手動更新、テキストダウンロード、ログ消去、管理画面へ戻るリンク。
- OTAパスワード設定済みなら **admin** と同じパスワードで認証。未設定なら認証なし。
- 起動段階、リセット理由、Wi-Fi/APRS-IS状態、ADCエラー集計、OTA受信量・中止理由・検証結果を記録。
- 高頻度のHEALTHログ、RF/ISパケット本文、パスワードはWebログへ常時記録しません。

RAMログは再起動で消えます。直前のOTA状態（受信中/失敗/検証済みと受信量）だけは小さなRTCメモリーへ記録し、
ソフト再起動後に `[PREVIOUS OTA]` として表示します。**電源断・ブラウンアウト等では保持を保証しません。**
Flashへの常時ログ書き込みは行いません。

## Web OTA

1. OTA passwordを8〜63文字で設定してSave & Reboot。認証ユーザー名は **admin**。
2. **Wi-Fi firmware update (OTA)** を開き直し、本機用のアプリ単体`.bin`を選択。
3. 同梱の `firmware/APRS_iGate_C3_v0.7_OTA.bin` で確認できます。merged/bootloader/partitionsは使用しません。
4. **更新開始**を押すと、2KBごとの本体受信確認と進捗率を表示します。
5. 全量受信・イメージ検証後、2秒の猶予を置いて再起動。画面は約30秒後に再接続を確認します。
6. 版番号、稼働時間、設定保持、VERIFIEDと、ログのPREVIOUS OTAを確認してください。

### v0.7の変更

- 大きなmultipart 1回の送信から、2KBデータ単位の短いHTTPリクエストへ変更。
- 16進テキストを本体でバイナリへ復元。ゼロバイトを含むデータをStringへ直接格納しません。
- 認証・起動ごとのトークン・セッションID・サイズ・オフセットを照合。受信確認後に次のブロックを送信。
- 応答を失ったブロックの自動再送はせず、二重書き込みを防ぎます。
- HTTP成功応答直後の即時再起動を避け、2秒後にメインループで再起動。
- 通信断だけで成功とは判断しません。ログと再接続後の状態を確認します。

### 更新中と異常時

- 更新中はRF復調・転送を休止。ADC DMAは維持し、ADCタスクで読み捨てます。
- DMA停止・再開は追加せず、中止・失敗後は復調状態をリセットして再開します。
- **中止**は現在のブロック応答後に本体へ通知します。
- 通信断等で中止が届かなければ、最終受信確認から**120秒**でセッションを解除。
- セッション中のWeb設定保存・再起動・初期化は拒否。本体ログとOTA状態は取得可能です。
- フラッシュ書き込み中はWeb応答が遅れ、ADC overflowが増えることがあります。
- 検証成功前の中止・失敗では稼働アプリを切り替えません。給電は維持してください。
- 新アプリ自体の起動不良を検出して旧版へ戻す機能はありません。USB復旧が必要です。
- HTTPを使う同一LAN内向けです。Webポートをインターネットへ公開しないでください。

## 従来機能

- RF受信→APRS-IS転送（qAO）。RF送信・デジピーター・INET→RF転送は行いません。
- 自局位置は緯度・経度を設定して有効化。認証後初回、以後30分間隔でAPRS-ISへ送信。
- Gridは保存のみ。Commentは半角英数字・記号で40文字以内（40バイト上限）。
- 設定保存・Web再起動・初期化後は60秒でトップへ自動遷移。IP変更時は新しいIPで開き直します。
- LCD：15分ごとに3画面×4秒×2周＝約24秒点灯。短押し60秒、設定AP中の点灯を維持。
- 正常時LED：30秒周期の0〜10秒Wi-Fi、10〜20秒APRS、20〜30秒両方消灯。
- SETUPは離した時に判定：短押しLCD、5秒以上15秒未満AP、15秒以上全設定消去。
- 初期設定AP：APRS-iGate-XXXX / aprssetup / http://192.168.4.1/。
- 通常Web：http://aprs-igate.local/ または本機のIP。

## 再設置前の実機試験

1. USB導入後、Rev0.7、既存設定、VERIFIED、本体ログを確認。
2. 同じv0.7をWeb OTAで送信。受信進捗→検証→再起動→再接続→PREVIOUS OTAを確認。
3. 途中で中止し、セッション解除・受信再開を確認。
4. 途中でブラウザーを閉じ、120秒後にログを確認。必要なら新規セッションで再試行。
5. 同じ版への更新は版番号だけでは判別できません。稼働時間とログも確認します。

コンパイル・PCテストと実機成功は別です。v0.5の通信断原因を確定・解消したとはまだ主張しません。
詳細は `TEST_NOTES.md`、同梱PDFガイド、`CHANGELOG.md` を参照してください。

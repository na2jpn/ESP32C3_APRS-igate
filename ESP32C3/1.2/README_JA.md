## v0.12：音量計と本体での5秒ピーク保持

管理画面の「音声入力モニター / 波形・レベル」、または `http://本機IP/audio` を開きます。
認証は従来どおりadmin＋OTAパスワード（設定済みの場合）です。

- 緑バー：直近5個の40ms区間、約200msのAC RMS。測定平均からDC成分を除きます。
- 赤線：本体で連続集計した直近約5秒の最大40ms AC RMS。
  ブラウザーが取得しなかった区間も対象です。取得や別ブラウザーの閲覧で消費しません。
  高い値から約5秒経過すると、その時点で残っている区間の最大値まで下がります。
- 表示更新は約1秒間隔で、通信状況によって遅れます。
  集計自体は閲覧中のADCデータ全区間に対して行い、短い音をピークに残します。
  40ms未満の音は区間平均になるため、瞬間的なサンプル最大振幅そのものではありません。
- dBFSの基準は2048 ADCコード。%はその基準への線形比で、電波のS値・校正音圧ではありません。
- 波形は従来どおり最新40msの抜粋（264組の最小・最大）。音量計の200msとは別の測定窓です。
  波形40ms RMS、波形ピーク、ADC平均、Min/Max、端付近の数も別に表示します。
- 波形の固定倍率×1/×4/×16・自動倍率×1〜×32を継承します。
  倍率変更は波形だけに適用し、音量計の値を拡大しません。
- 一時停止は表示と値を保持します。要求停止から約3秒で本体のモニター計算が休止し、
  再開後は新しい履歴を作ります。APRS受信自体は表示停止で止まりません。
- 別タブで非表示、ページを閉じる、通信断による要求停止でも約3秒で休止。
  再試行待ちが3秒を超える場合も履歴はリセットされます。無人の常時記録ではありません。
- ADC読み取り失敗、データ欠落、復旧やOTAでは履歴を破棄します。
  無効な測定を音量ゼロとして表示せず、通信断でも古い値を消します。
- モニター固定RAMは3232B（v0.11から1048B増）。HTTP応答の一時ヒープは別です。
  追加のADC起動や新規タスクはありません。

### AMP追加を判断するための確認

入力された音のピークを比較しやすくなります。

音量計・赤線・波形の振幅、上下限への張り付き、1200/2200Hz検出値、DMA欠落を併せて確認します。
音声経路が通ることだけでは、増幅不要・増幅必須のどちらも確定しません。
実電圧校正、RF感度、通常局のAPRS受信率、実機の追加CPU負荷は未検証です。
2026-11-02のv0.12実機試験では、1200bps試験WAVのRF受信・正常復調・APRS-IS転送・aprs.fi位置表示まで確認しました。

v0.11からの変更は音量計の集計・表示です。RFゲイン、DRA音量、復調しきい値、
ADC復旧処理、位置ビーコン、OTA、NTP、LCD/LEDは継承します。

## v0.10での変更と確認方法

v0.9実機ログで、Samplesが固定されたままTimeoutだけが増える状態を確認しました。
再起動後は実データが戻っています。停止を起こした根本原因は未確定です。
本版は受信停止の検知と復旧・記録を追加するもので、RF復調成功を保証するものではありません。

- 有効なADCデータが3秒来なければ、ADCタスク自身がstop→flush→startを実施します。
  3秒以上の間隔を空け最大3回。その後はFAULT表示を維持し、無限再試行や装置全体の自動再起動はしません。
  API成功後もRECOVERING表示を維持し、実データ受信後に復旧成功を記録します。
  有効データが継続する30秒間に読み取り失敗・欠落がなければ、試行回数の枠を戻します。
- 管理画面の「ADC取り込みを復旧」は同じ復旧処理を予約します。
  OTA中は409で拒否、ADC初期化失敗時は503で再起動が必要です。
  OTAパスワード設定時はadmin認証、未設定時も起動ごとのトークンを検証します。
- ADC表示：OK / STALE（データ鮮度1.5秒超・未受信など）/ RECOVERING /
  FAULT / PAUSED（OTA）/ INIT FAILED。初期化に成功しただけでOKにしません。
- モニターにTimeout、実取得サンプル数、最終取得からの時間、取得速度、復旧試行/成功数、
  意図的な破棄数を追加。本体ログは状態変化と10秒単位のoverflow/read error/timeout増分を記録します。
- 受信CSVの末尾に `adc_valid` 列を追加。1は実測、0は読み取り失敗です。
  `adc_valid=0` のRMS=0やMin/Max=2048は代用値であり、無音・実際のADC電圧を示しません。
- DMAプール8KB→16KB、ADCタスク優先度1→2。スタックは6144Bを維持し、
  最大4バッファ処理ごとに1tick休止します。欠落時は同期をリセットし最大32バッファを破棄します。
  DSPの毎サンプルの浮動小数点除算を同じ判定式の乗算比較へ変更しました。
  RFゲイン・AF音量・復調しきい値はv0.9から変更していません。
- 通常時のWi-Fi断は60秒継続してから設定APへ移行します。
  AP開始やWi-Fiスタック再初期化後はADC復旧を予約します。これが停止原因だと確定したわけではありません。
- v0.9のOTA再送・SHA256照合、位置ビーコン、NTP、LCD、LED、保存設定を継承します。

導入済みv0.9からは通常のWeb OTAで同梱のv0.10アプリbinを送信してください。
再接続後にRev0.10、APRS-IS VERIFIED、Samples/Captureの増加、Timeout・overflowの推移を確認します。
停止が再発した場合は、本体ログと受信CSVを再起動前に保存してください。
RAMログは電源断・再起動で消えます。長期間の無人保持はできません。

## v0.9以降でのWeb更新

1. 管理画面のOTAリンクを開き直し、アプリ単体binを選択。
2. 「更新開始・再開」でSHA-256を計算し、1KBずつ送信します。
3. 通信断時は1/2/4/8/15秒（上限15秒）の間隔で受信位置を照合し、未受信分から継続。
4. 全量受信・SHA-256照合・イメージ検証後、2秒後に再起動。
5. 約30秒後から再接続を確認。版番号・稼働時間・本体ログ・VERIFIEDを確認。

- 1リクエストは30秒で打ち切り。操作ごとの復帰待ちは進捗なしで最大約8分。
- 更新全体に5分/8分の制限はありません。受信確認が続く限り継続します。
- 本体は最後の新規データ受信から10分で解除。状態照会や同一ブロック再送だけでは延長しません。
- 更新中もWi-Fi自動再接続と15秒間隔の再接続要求を行います。
  通常経路のAPRS再接続・AP移行・Wi-FiモードOFF/ON・長時間障害の強制再起動はOTA中に行いません。
- 受信・転送は更新中休止します。完全な無通信が続く場合は最長10分休止します。
- 中止ボタンも本体の応答を確認してから中止と表示します。届かない場合はタイムアウトで解除。
- 検証確定後の中止はできません。検証結果の照合中は結果確認を優先します。

### ページを閉じた・開き直した場合

本体の電源とセッションが維持されていれば、**同じブラウザー・同じURL（同じorigin）で
同じbinを選び、「更新開始・再開」**を押すと続行できます。
ファイル名ではなく全体SHA-256、サイズ、起動トークン、クライアントキー、セッションIDを照合します。
ブラウザーにはキー等のメタデータだけを保存し、ファイル本体・認証パスワードは保存しません。
localStorageが禁止されている場合、同じページ内の復帰はできますが、再読込後のキー保持はできません。
別ブラウザー・別URL・別ファイルへの自動引き継ぎはしません。10分経過で解除された後は最初から送ります。

### 応答が失われた場合の保険

- 開始要求は同じキー・SHA・サイズなら同じセッションを返し、Flashを再初期化しません。
- 書き込み済み位置を確認してから次へ進みます。
- 直前と同じオフセット・長さ・SHA-256のブロック再送はACKだけ返し、二重書き込みしません。
- 受信全体のSHA-256も本体で計算し、申告されたファイルのSHAと一致しなければ検証・起動切替をしません。
- 本体の起動トークンが変わった場合、送信途中のセッションは再開しません。
- 検証応答だけ失われて既に再起動した場合、対応ファームのRTC記録に同じSHA・キー・サイズの
  検証成功が残っていれば照合できます。対象ファームが新形式に非対応、電源断、RTC消失なら成功とは断定しません。

本体のIPが変わった場合、ブラウザーが別アドレスへ自動追従する機能はありません。
給電・Wi-Fi環境・ブラウザーのスリープ等、通信断そのものを防ぐ保証ではありません。
新アプリが起動不能になったときの自動ロールバックは未実装で、USB復旧が必要です。
SHA-256はファイル同一性と整合性の確認であり、署名による配布元認証ではありません。

## まず診断記録を取る

1. 管理画面の **受信変化の記録 / RX diagnostics**（`/rxdiag`）を開く。
2. 必要なら「記録消去・再開」。約1秒、普段の音声レベルを学習させる。
3. 既知のAPRSパケットを送信する。
4. 送信後、速やかに「記録停止」→「CSVダウンロード」。録画は不要。
5. 自動記録が出ない場合は「記録再開」→「手動記録」を押してすぐ送信する。

音声のRMS上下変化、トーン合計・比率変化、ADC端付近、CRC・正常フレーム・
フレーム異常・DMA overflow・読み取り異常のカウンター変化をADCタスクで監視します。
雑音も記録対象です。記録があること自体はAPRS受信成功を意味しません。

- 約20ms（528サンプル）ごと。直前最大8行（160ms）＋開始点以後、合計最大48行（約960ms）。
- 最大4イベント。古いイベントから上書き。再起動・電源断で消えるRAM記録。
- 通常時、イベント終了後500msの再トリガー待機あり。正常フレーム・手動開始は待機を迂回。
- 1イベントの全期間を必ず収録する録音機能ではありません。raw音声は保存しません。
- RMSは復調器の平滑電力の区間平均から算出。1200/2200Hz値は各20ms区間末尾の検出値。
- ADC Min/Maxは区間全体。カウンターは累計と行間差分。最初の行の差分は0。
- ADC読み取り失敗の行はサンプル数不変、Min/Max=2048の便宜値。波形として解釈しません。
- イベントのreasonは期間中の理由のビット合計。trigger=1は開始行。complete=0は途中の記録。
- OTA中は記録を休止し、CSV取得・記録操作を拒否。完了後に確認してください。
- 雑音の変化が続くと4件が短時間で入れ替わるため、試験後は速やかに記録停止して保存。
- 本体イベントログ（4KB、`/logs`）とは別枠。どちらもOTAパスワード設定時はadmin認証。

初期しきい値：RMSは基準比30%かつ絶対差0.012以上、トーン合計は35%かつ0.006以上、
トーン比は0.45以上（合計0.008超）。比較は厳密には「超えた場合」。
ADC端付近は0〜16または4079〜4095。
平常値は約1秒の初期学習後、イベント外で追従します。
これは初期試験値です。取り逃し・雑音反応を実機CSVで評価します。

## NTP日時

Wi-Fi接続後、NICT / Cloudflare / pool.ntp.orgへ非同期で時刻合わせします。
受信開始を時刻同期待ちで止めません。JST表示です。

- 同期前はUNSYNCと起動からの経過msのみ。
- 同期後はJST日時（ミリ秒表示）と64bitの経過msを両方保存。
- 同期前の記録を後から同期済み日時へ書き換えません。
- 時計補正が起きても既存の記録日時は維持。順序・間隔の確認は経過msを使います。
- 管理画面のClockには最終同期からの経過秒も表示。通信断後は同期時点からの推定時計です。
- 記録日時はADCデータを処理した時点です。DMAバッファ遅延を含み、RF到来時刻の精密測定ではありません。
- ミリ秒表示は時刻精度を保証する意味ではありません。NTP実通信は実機確認が必要です。

## 継承機能・資料

位置ビーコンは有効時に認証後初回と以後30分。Gridは保存のみ。Commentは40バイト以内。
LCDは15分ごとに3画面×4秒×2周（約24秒）。短押し60秒。
正常LEDは30秒周期：0〜10秒Wi-Fi、10〜20秒APRS、20〜30秒両方消灯。
SETUPは離した時に判定：短押しLCD、5〜15秒未満AP、15秒以上全設定消去。
AP：APRS-iGate-XXXX / aprssetup / http://192.168.4.1/。
通常：http://aprs-igate.local/ または本機IP。設定保存後は60秒でトップに遷移します。
